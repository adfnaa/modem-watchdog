# 光猫看门狗（modem-watchdog）

周期性 ping 外网判断宽带是否可用；确认掉线超过设定时长后，通过**米家智能插板**（局域网 miIO 协议）给光猫断电，等几秒再上电，完成一次物理重启。带冷却期、熔断保护和完整日志，并提供网页管理界面。

两套实现功能对齐，按部署环境二选一：

| 形态 | 文件 | 运行位置 | 适合场景 |
|---|---|---|---|
| **服务版** | [`modem-watchdog.go`](modem-watchdog.go) + [`docker-compose.yml`](docker-compose.yml) | 服务器 / NAS / 软路由（Docker） | 有 7×24 开机设备；功能更全，配置可持久化（也可纯内存运行） |
| **固件版** | [`modem-watchdog.ino`](modem-watchdog.ino) | ESP32-C3 | 不依赖服务器；功耗低、断电自恢复 |

判定的规则、保护机制、`/status` 字段与日志文案两版一致，差异见 [§12](#12-两版差异与已知限制)。

## 1. 工作原理

### 1.1 检测

按 `检测间隔`（默认 15 秒）ping 外网，目标 1 通即算在线；不通再测目标 2，两个都不通才算"本次失败"（短路逻辑，省时间）。

### 1.2 判定

单次丢包很常见，因此**必须连续 2 次检测都失败**才开始计"断网时长"；持续超过 `断网阈值`（默认 10 分钟）才触发动作。

> 固件版额外前提：WiFi 未连接时不检测（链路都不通，判不出外网状态）。

### 1.3 动作

```
重新握手 → 关闭插板电源 → 等待「断电时长」(默认 10s) → 打开插板电源 → 进入冷却期
```

每一步都要求**设备明确确认**：收到带有效校验和、且 `id` 与请求一致的响应才算成功。设备不回包或报错时最多重试 3 次，仍失败则如实记录"动作未完成"，绝不假装成功。

### 1.4 三层保护

| 机制 | 默认值 | 作用 |
|---|---|---|
| **冷却期** | 2 分钟 | 重启动作完成后暂停检测，给光猫和宽带留启动时间 |
| **熔断** | 连续 5 次 | 累计触发 5 次重启动作（**含未完成的动作**）后停止一切自动动作，只留日志与告警，等人工介入。防止"Ping 目标被运营商屏蔽"或"插板不可用"时无限断电光猫 |
| **稳定在线期** | 5 分钟 | 网络恢复后**不立即**清零计数与熔断，必须连续在线满 5 分钟才清零。否则"重启后能撑几分钟又断"的老化光猫永远触发不了熔断，会长期每 (阈值+冷却) 真断电一次 |

熔断状态**会持久化**（服务版写在 `<配置文件>.state`，固件版写在 NVS），重启进程/容器/设备不能绕过熔断。网络连续在线满 5 分钟后自动解除，也可在管理页点「清除熔断状态」手动解除。

### 1.5 状态流转

```
        ┌────────────── 在线 ──────────────┐
        │                                  │
   检测失败 ×1 → 检测失败 ×2 → 断网计时中 → 达到阈值 → 重启动作
        │                                  │            │
        └──────── 任一次成功 ◄─────────────┘            ▼
                                                  冷却期中（不检测）
                                                        │
                                                        └→ 回到"在线"判定
```

## 2. 部署前必读

### 2.1 看门狗自己不能依赖被断电的那路网络

如果 ESP32 连的是光猫自带 WiFi、或容器跑在"光猫一体机"下游，插板一断电看门狗自己也断网了 —— 它会**发不出"上电"命令**，光猫会一直停在断电状态，需要人工合闸。

正确做法：让看门狗连在**不受该插板控制**的网络/电源上（例如光猫改桥接 + 独立路由器，插板只控制光猫）。

> 这种"上电未确认"的情况两版都会记为硬故障并高分贝告警，不会静默。

### 2.2 同一个插板只能被一个看门狗控制

固件版和服务版同时跑会互相抢插板，导致奇怪的断电时序。二选一。

### 2.3 先手工验证两件事

1. `ping <PING_IP1>` 通不通；
2. 用 `miiocli` 之类工具能否用这个 IP + Token 控制插板。

这两件事没确认就上线，最可能的结果是"看门狗一直在重启光猫"。

## 3. 服务版（Docker）

### 3.1 前置条件

- 7×24 开机的 Linux 主机（NAS、软路由、小主机均可），已装 Docker + Compose
- 米家 / 小米生态**智能插板**，已接入 2.4G WiFi，可局域网控制
- 插板的 **IP 地址**与 **miIO Token**（32 位十六进制）

> Token 获取请参考社区工具（`python-miio` 的 `miiocli device --ip <IP> --token <TOKEN> info`、各种 miIO Token 提取脚本）。本仓库不提供 Token 提取工具。

### 3.2 选运行模式：持久化 / 纯内存

两种模式**都是受支持的用法**，按需选一个：

| 模式 | 怎么用 | 效果 |
|---|---|---|
| **持久化**（推荐） | 挂载 `./data:/data`（compose 里默认已启用） | 配置与访问密码写入 `./data/config.json`，容器重启后保持 |
| **纯内存** | 注释掉 `./data:/data` 这一行，**或**显式设 `CONFIG_FILE=` | **不写任何文件**；改动只在内存生效，进程重启后回到环境变量配置 |

**选持久化**：先准备好目录属主，否则程序会自动降级为纯内存模式：

```bash
cd <项目目录>
mkdir -p data
sudo chown 1000:1001 data     # 与 compose 里的 user: 1000:1001 保持一致
```

> 原因：程序以 uid 1000 运行，Docker 自动创建的目录属主是 root，容器内写不进去。

**选纯内存**：建议同时设固定密码，否则每次重启都要去日志里翻新生成的随机密码：

```yaml
    environment:
      WEB_PASSWORD: "你的密码"
```

启动日志会说明当前处于哪种模式，不需要猜：

```
配置持久化：已启用（/data/config.json）           ← 持久化模式
                                                   ↓ 纯内存模式（自动降级）
配置持久化：已关闭 —— 无法使用目录 /data: mkdir /data: permission denied
  Web 上的修改只在内存中生效，进程重启后回到环境变量配置
  （这是预期行为，不是故障：不挂载数据卷即可实现"不落盘"运行；
    若想显式关闭持久化，把环境变量设为 CONFIG_FILE= 即可）
  提示：纯内存模式下访问密码每次启动都会重新生成，建议设置 WEB_PASSWORD 固定下来
配置文件     : （纯内存模式，不写文件）
```

纯内存模式下保存配置会返回"**配置已在内存中生效**（当前为纯内存模式，不写文件…）"——正常结果，不是错误。

### 3.3 编辑 `docker-compose.yml`

先按 §3.2 决定是否保留 `./data:/data`（不需要持久化就注释掉），然后至少改两项：

```yaml
environment:
  DEVICE_IP: "192.168.0.88"                           # ← 插板的局域网 IP
  DEVICE_TOKEN: "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"    # ← 插板的 miIO Token
```

可选：设固定访问密码（不设置则首次启动随机生成并打印到日志）：

```yaml
  WEB_PASSWORD: "你的密码"
```

### 3.4 启动

```bash
docker compose up -d
docker compose logs -f modem-watchdog
```

日志里会看到启动信息、配置路径，以及（首次启动时）随机生成的访问密码：

```
=== 光猫看门狗启动 ===
...
远程管理已开启: http://<本机IP>:8848/  （用户名 admin）
★ 首次启动生成的访问密码: xxxxxxxxxxxx
```

浏览器打开 `http://<主机IP>:8848/`，用户名 `admin`，密码用日志里那个（或你设的 `WEB_PASSWORD`）。

### 3.5 更新程序

```bash
docker compose up -d --force-recreate
```

容器入口会把挂载进来的二进制复制到 `/tmp` 再执行，`--force-recreate` 能确保复制到最新版本。

## 4. 固件版（ESP32-C3）

### 4.1 前置条件

- ESP32-C3 开发板（其它 ESP32 型号也可，注意改 LED 引脚）
- **Arduino IDE 2.x**（或 `arduino-cli`）+ **esp32 core 3.x**
- 库：**ESP32Ping**（库管理器搜索安装）
- 插板的 IP 与 miIO Token

### 4.2 编译与烧录

1. Arduino IDE 打开 [`modem-watchdog.ino`](modem-watchdog.ino)
2. 开发板选 `ESP32C3 Dev Module`
3. 编译并上传（本仓库实测：**Flash 约 80%**、静态 RAM 约 16%）

烧录前必须改文件开头的默认值（NVS 为空时用的就是它们）：

```cpp
char WIFI_SSID[33]     = "";                                    // ← 你的 WiFi 名（必填）
char WIFI_PASSWORD[65] = "";                                    // ← 你的 WiFi 密码（必填）
char DEVICE_IP[16]     = "192.168.0.88";                        // ← 插板 IP（必须 IPv4）
char DEVICE_TOKEN[33]  = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx";    // ← 插板 Token（32 位十六进制）
```

> ⚠️ **WiFi 必须在首次烧录前填好**：固件没有 AP 配网兜底，连不上 WiFi 就一直停在重连循环里，配置页自然也打不开，只能重新烧录。
> ⚠️ 本仓库已把这些值留空/置为占位符。**你自己填上真实口令和 Token 后，切勿提交或分享这个文件**（它们是明文存储的）。

### 4.3 首次开机

串口监视器（115200）会看到：

```
=== 光猫看门狗启动 ===
配置已加载：WiFi="..." 插板=... siid=2/piid=1 Ping=.../...
看门狗阈值：检测 15s / 断网 600s / 冷却 120s / 断电 10s / miIO重试 60s / 最大重启 5 次
离线兜底：运行中按住 BOOT 键 5 秒可恢复出厂配置
远程管理已开启: http://192.168.x.x/（已启用访问鉴权（用户名 admin））
首次运行：使用编译期默认访问口令 "admin"（用户名 admin），请尽快在配置页修改
```

浏览器打开 `http://<设备IP>/`，用户名 `admin`、口令 `admin`，**第一件事就是改访问口令**。

### 4.4 LED 指示灯（默认 GPIO8，低电平点亮）

| 现象 | 含义 |
|---|---|
| 熄灭 | 一切正常 |
| 慢闪（500ms） | WiFi 未连接，正在重连 |
| 常亮 | miIO 异常（Token 错 / 插板离线 / 握手失败） |
| **快闪（150ms）** | **熔断或硬故障（如"上电命令未确认"），需要人工介入** |

### 4.5 BOOT 键兜底（GPIO9）

**设备运行期间**长按 BOOT 键 5 秒 → 恢复出厂设置并重启（清空 NVS，回到固件文件里的默认值）。

> ⚠️ 必须"运行中"按。ESP32-C3 的 GPIO9 是 strapping 引脚，**上电瞬间按住它会直接进入 ROM 下载模式**，程序根本不会启动，所以不存在"开机长按"这条路。
> 若 WiFi 连不上，设备会一直停在联网阶段——此时 BOOT 键检测仍在运行（联网循环里也会检测），所以这条路依然可用。

### 4.6 配置存储

全部配置存 **NVS**（断电不丢）；访问口令以 **SHA-256** 存储，不存明文。写 NVS 只发生在"保存配置""恢复出厂""熔断状态变化"时，频率极低，不会磨损 flash。

## 5. 环境变量全表（服务版）

| 变量 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| `DEVICE_IP` | **必填** | IPv4 | 插板局域网地址 |
| `DEVICE_TOKEN` | **必填** | 32 位十六进制 | 插板 miIO Token |
| `SIID` | `2` | 1–9999 | 电源属性 siid（常见插座为 2） |
| `PIID` | `1` | 1–9999 | 属性 ID（常见插座为 1） |
| `MI_PORT` | `54321` | 1–65535 | miIO 端口 |
| `PING_IP1` | `223.5.5.5` | IPv4 | 首选 ping 目标 |
| `PING_IP2` | `8.8.8.8` | IPv4 | 备用 ping 目标 |
| `PING_INTERVAL` | `15s` | 5s–1h | 检测间隔 |
| `PING_TIMEOUT` | `1s` | 0.5s–10s | 单次 ping 超时 |
| `OFFLINE_THRESHOLD` | `10m` | 30s–24h | 连续断网多久后触发重启 |
| `REBOOT_COOLDOWN` | `2m` | 10s–1h | 重启动作完成后的冷却时间 |
| `REBOOT_OFF_TIME` | `10s` | 5s–2m | 插板断电时长 |
| `MIIO_RETRY_INTERVAL` | `1m` | 5s–1h | miIO 握手失败后的重试间隔 |
| `ONLINE_STABLE` | `5m` | 30s–24h | 连续在线多久才清零重启计数/熔断 |
| `MAX_REBOOT_ATTEMPTS` | `5` | 1–10 | 熔断阈值 |
| `WEB_PORT` | `8848` | 1–65535 | 管理页面端口 |
| `WEB_LISTEN` | 空 | IP | 监听地址；空 = 所有接口，`127.0.0.1` = 仅本机（容器内改这个等于关闭外部访问） |
| `WEB_PASSWORD` | 空 | 任意 | 访问密码。**显式设置后优先级最高**，会覆盖 Web 上改的密码 |
| `CONFIG_FILE` | `/data/config.json` | 路径 / 留空 | 持久化路径。**显式留空（`CONFIG_FILE=`）= 关闭持久化**，纯内存运行、不写文件；删除该文件即"恢复出厂"。启动时实测可写性，不可写则自动降级为纯内存模式 |
| `LOG_BUFFER_SIZE` | `8388608`（8 MiB） | 64KiB–256MiB | 内存日志环形缓冲大小（只占内存、不落盘） |
| `SOURCE_BINARY` | `/src/modem-watchdog` | 路径 | 容器内源二进制路径，用于"重启进程"时判断是否需要让容器重新复制新版本 |
| `PUID` / `PGID` | `0` / `0` | ≥0 | 降权目标；**必须同时设置或同时为 0**（都为 0 = 不降权） |
| `TZ` | 空 | 时区名 | 如 `Asia/Shanghai`（时区库已内嵌，无需装 tzdata） |

**时长写法**（两版一致）：`15s`、`10m`、`1h`；可串联 `1m30s`、`1h30m`；纯数字 = 秒（`600`）。**不支持**小数（`1.5h`）与毫秒（`500ms`）—— 所有时长下限都是 5 秒，用不到亚秒精度。

## 6. 配置页字段（固件版）

配置页分四组，**留空一律表示"保持不变"**（不会报错）。

**WiFi**

| 字段 | 说明 |
|---|---|
| SSID | 新 WiFi 名。**留空 = 沿用当前 SSID**（只改路由器密码时 SSID 留空即可） |
| 密码 | 新 WiFi 口令。留空 = 沿用当前口令 |

保存后立即返回"已接受"，真正的切换由主循环在 800ms 后异步执行：**20 秒内连不上新 WiFi 就自动回退旧配置**，不会把设备锁在门外。

**插板 miIO**

| 字段 | 范围 | 说明 |
|---|---|---|
| 插板 IP | IPv4 | 保存后立即重握手验证 |
| Token | 32 位十六进制 | 留空 = 不修改 |
| siid / piid | 1–9999 | 常见插座为 2 / 1 |

**看门狗参数**（立即生效并存入 NVS）

| 字段 | 默认 | 范围 |
|---|---|---|
| Ping 目标 1 / 2 | `223.5.5.5` / `8.8.8.8` | IPv4 |
| 检测间隔 | `15s` | 5–3600 秒 |
| 断网阈值 | `10m` | 30–86400 秒 |
| 重启冷却 | `2m` | 10–3600 秒 |
| 插板断电时长 | `10s` | 5–120 秒 |
| miIO 重试间隔 | `1m` | 5–3600 秒 |
| WiFi 重连间隔 | `10s` | 3–600 秒 |
| 最大连续重启次数 | `5` | 1–10 |

**Web 访问**

| 字段 | 说明 |
|---|---|
| 访问密码 | 留空保持不变；只存 SHA-256，不存明文 |
| 清除密码 | 关闭鉴权；**该状态会持久化**，重启后不会自动恢复成某个密码 |
| HTTP 端口 | 1–65535，**重启控制器后生效** |

## 7. 管理页面

两版页面结构相同：顶部徽章显示实时状态，下面三个标签页（日志 / 控制 / 配置）。

### 7.1 状态徽章

| 徽章 | 含义 |
|---|---|
| 运行 xx | 已运行时长（服务版是进程，固件版是设备） |
| WiFi 已连接 / WiFi 断开（仅固件版） | 链路状态；带 IP 与 RSSI |
| 外网正常 / 断网 xx | 当前判定结果 |
| 重启冷却中 | 刚执行过重启动作，冷却期内不检测 |
| miIO 正常 / 异常 | **最近一次** miIO 交互结果 |
| 重启 n/N | 已触发重启动作次数 / 熔断阈值 |
| 看门狗待命 / 已熔断 · 需人工介入 | 是否处于熔断 |
| 任务执行中（动作名） | 有手动任务正在执行 |
| 未设置访问密码 | 鉴权已关闭（醒目提示） |

### 7.2 日志页

- 自动每 2 秒刷新（可关闭），也可点「立即刷新」
- 服务版是**增量拉取**：只取新增字节，不会每 2 秒重传整个缓冲
- 「原始日志 /log」「状态 JSON /status」两个链接可用于脚本化或第三方监控

### 7.3 控制页

| 按钮 | 动作名 | 需要确认 | 说明 |
|---|---|---|---|
| 清除熔断状态 | `clear_fatal` | 否 | 立即解除熔断并清零重启计数 |
| 重启控制器 / 重启看门狗进程 | `restart_self` | 是 | 固件版重启 ESP32；服务版原地重启进程（若检测到二进制已更新，会退出让容器重新复制新版本） |
| 恢复插板供电 | `power_on` | 是 | 补救用：插板停在断电状态时手动合闸 |
| 断电重启光猫 | `reboot_modem` | 是 | 完整的"断电 → 等待 → 上电"流程 |
| 恢复出厂设置 | `factory_reset` | 是 | 清除全部配置并重启，回到环境变量 / 固件文件里的默认值 |

**同一时刻只允许一个任务**：执行期间再点按钮返回"已有任务在执行，请稍候"（HTTP 409）。

> 手动触发的重启**不计入**熔断计数——熔断只约束看门狗自己的自动动作。

### 7.4 配置页

见 [§6](#6-配置页字段固件版)（固件版）与 [§5](#5-环境变量全表服务版)（服务版；服务版可改字段与固件版基本一致，另多出"单次超时""监听地址"等）。

## 8. HTTP API

所有接口都需要 HTTP Basic Auth（用户名固定 `admin`；关闭鉴权则不需要）。

### 8.1 `GET /status`

下面的示例把两版字段合并展示（`wifi`/`ip`/`rssi` 仅固件版有，`configFile` 仅服务版有）：

```json
{
  "ver": "1.0",
  "uptime": 12345,
  "wifi": true,          "ip": "192.168.0.50",  "rssi": -58,
  "miio": true,
  "online": true,
  "linkDown": 0,
  "rebooting": false,
  "reboots": 0,          "maxReboots": 5,
  "fatal": false,
  "pending": "",
  "logUsed": 812,        "logTotal": 8388608,
  "logSeq": 4211,
  "webPort": 8848,
  "auth": true,
  "configFile": "/data/config.json"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ver` | string | 版本号 |
| `uptime` | number | 已运行秒数 |
| `wifi` / `ip` / `rssi` | bool / string / number | **仅固件版**有 |
| `miio` | bool | 最近一次 miIO 交互是否成功 |
| `online` | bool | 当前是否判定为外网可达 |
| `linkDown` | number | 已断网秒数；0 = 在线 |
| `rebooting` | bool | 是否处于重启冷却期 |
| `reboots` / `maxReboots` | number | 已触发重启次数 / 熔断阈值 |
| `fatal` | bool | 是否已熔断 |
| `pending` | string | 正在执行/待执行的动作名，空闲为 `""` |
| `logUsed` / `logTotal` | number | 内存日志缓冲已用/总字节 |
| `logSeq` | number | 日志版本号（单调递增），用于判断有无新日志 |
| `webPort` | number | 当前**实际监听**的端口 |
| `auth` | bool | 是否启用了访问鉴权 |
| `configFile` | string | **仅服务版**有：配置文件路径；纯内存模式下为空字符串 `""` |

### 8.2 `GET /log[?since=N]`

纯文本日志。

- 不带参数：返回全量，响应头 `X-Log-Reset: 1`
- 带 `since=N`：只返回第 N 字节之后的新增内容；若 N 太旧（已被环形缓冲覆盖），回退为全量并置 `X-Log-Reset: 1`
- `X-Log-Seq` 头返回当前日志版本号

### 8.3 `GET /api/config`

返回当前配置（敏感字段不回传明文，只回 `hasToken` / `hasPassword` 之类的布尔标记）：

`deviceIp` `hasToken` `siid` `piid` `miPort` `ping1` `ping2` `pingInterval` `pingTimeout` `offlineThreshold` `rebootCooldown` `rebootOffTime` `miioRetry` `maxReboots` `webPort` `hasPassword` `webAuthDisabled`（服务版另有 `webListen`、`configFile`；固件版另有 `wifiSsid`、`wifiRetry`）

> 时长字段一律以**秒数**回传，例如 `"pingInterval": 15`。

### 8.4 `POST /api/config`

表单编码（`application/x-www-form-urlencoded`）。**留空 = 保持不变**；任何字段校验失败会整体拒绝，不会"改了一半"。

**服务版字段**：`device_ip` `device_token` `siid` `piid` `mi_port` `ping_ip1` `ping_ip2` `ping_interval` `ping_timeout` `offline_threshold` `reboot_cooldown` `reboot_off_time` `miio_retry_interval` `max_reboot_attempts` `web_password` `clear_web_password=1` `web_port` `web_listen`

**固件版字段**：`wifi_ssid` `wifi_pass` `dev_ip` `dev_token` `siid` `piid` `ping1` `ping2` `ping_interval` `offline_threshold` `cooldown` `reboot_off_time` `miio_retry_interval` `wifi_retry` `max_reboots` `web_pass` `clear_web_pass=1` `web_port`

> 两版的**表单字段名并不相同**（服务版用 `device_ip`/`ping_ip1`，固件版用 `dev_ip`/`ping1`），但 `GET /api/config` 的**返回字段名完全一致**——写第三方脚本时请以返回字段为准。

响应：`{"ok":true,"msg":"配置已保存并生效"}`；失败时 `ok=false`、`msg` 说明原因。

### 8.5 `POST /api/control`

表单编码，参数 `action=<动作名>`，危险动作还需要 `confirm=1`。

```
action = reboot_modem | power_on | restart_self | factory_reset | clear_fatal
```

响应：`{"ok":true,"msg":"已接受：..."}`；忙碌时 HTTP 409。

### 8.6 鉴权与防跨站

- **鉴权**：HTTP Basic Auth，用户名固定 `admin`，密码以 SHA-256 十六进制比对（常量时间比较）
- **防 CSRF**：写接口要求请求头 `X-Requested-With: watchdog`。跨站脚本要伪造自定义头必须先通过 CORS 预检，而本服务不回应预检，因此请求发不出去（服务版另外校验 `Origin` 同源）

## 9. 参数调优

### 9.1 ping 目标怎么选

- 必须是**公网 IPv4 地址**：不要填域名、IPv6、`0.0.0.0`、`127.0.0.1`，也不要填成插板自己的地址（这些会让看门狗"永远在线"或"永远离线"）
- 建议选**稳定的公共 DNS**：`223.5.5.5`（阿里）、`119.29.29.29`（腾讯）、`114.114.114.114`
- 默认值 `223.5.5.5` / `8.8.8.8` 
- **重要**：部分运营商/网络会屏蔽 ICMP。上线前先手工 ping 一下这两个地址；如果两个都不通，看门狗会在阈值时间后开始尝试重启光猫（这是配置错误，不是故障）

### 9.2 断网阈值 与 重启冷却

- `断网阈值` 太短（如 60 秒）会被宽带短暂 PPPoE 重拨、WiFi 抖动误触发 → 建议 **5–10 分钟**
- `重启冷却` 要**大于光猫启动+拨号所需时间**（一般 1–3 分钟）→ 建议 **2 分钟**起
- 两者之和就是"最坏情况下两次断电的间隔"

### 9.3 断电时长

插板断电多久再上电。太短可能光猫没完全放电，太长只是浪费时间 → **10 秒**通常够用。

### 9.4 熔断阈值

连续触发多少次重启后放弃自动动作。设太小会过早熔断（例如宽带故障需要更长时间恢复），设太大则可能反复断电 → 保持 **5** 即可。

### 9.5 稳定在线期

网络恢复后要"稳"多久才算真的好。设太小会退化成"一恢复就清零"，让老化光猫永远熔断不了；设太大会让计数清零变得迟钝 → **5 分钟**是较稳妥的折中。

### 9.6 检测间隔 与 单次超时

- 检测间隔 15 秒足够，调太小（<5 秒）没有意义还费电
- 单次超时 1 秒足够（公网 DNS 的 RTT 通常 <50ms）
- 注意：`单次超时 × 2` 不能超过 `检测间隔`，否则检测会挤在一起

## 10. miIO 协议要点

方便排障时对照（两版实现一致）：

- **传输**：UDP，目标端口 `54321`
- **握手**：发送 32 字节 `21 31 00 20` + 28×`FF`；设备回同样长度的包，从中取出 `deviceID`（第 8–12 字节）与 `stamp`（第 12–16 字节）
- **命令包**：`16 字节头 + 16 字节 checksum + AES-128-CBC 密文`
  - `key = MD5(token)`，`iv = MD5(key ‖ token)`
  - `checksum = MD5(header ‖ token ‖ 密文)`
  - 载荷：`{"id":1,"method":"set_properties","params":[{"siid":2,"piid":1,"value":false}]}`
  - PKCS#7 填充，`id` 固定为 `1`
- **确认**：设备返回的包必须满足"魔数正确 + 长度字段一致 + checksum 校验通过 + 解密后 `id` 等于 1"，才算这条命令被接受

> ⚠️ **关键提示**：握手成功**只能说明该地址上有一个 miIO 设备**，不能证明 Token 正确（32 字节的握手响应没有有效校验和，这一点与 `python-miio` 行为一致）。Token 是否正确由第一条命令能否收到有效响应来判定。
> 所以日志里出现 `握手成功 DID=...` 但随后反复 `设置电源(x) 第 n/3 次未确认` → **99% 是 Token 填错了**。

## 11. 安全与故障排查

### 11.1 安全说明

| 项目 | 现状 |
|---|---|
| 传输 | **明文 HTTP**，无 TLS。请只在**可信局域网**内使用 |
| 鉴权 | Basic Auth（用户名 `admin`）；服务版首次启动生成随机密码，固件版首次运行用编译期默认口令 `admin` |
| 关闭鉴权 | 页面提供"清除密码/关闭鉴权"，该状态**持久化**（纯内存模式下只在本次运行内有效）。关闭后同局域网任何人都能控制你的插板 |
| 纯内存模式的密码 | 未设 `WEB_PASSWORD` 时**每次启动都会生成新的随机密码**并打印到日志。想固定就显式设置 `WEB_PASSWORD` |
| 配置内容 | 服务版 `config.json` 权限 `0600`，内含**明文 `DEVICE_TOKEN`**；固件版 Token 存于 NVS（未加密） |
| Token 泄露后果 | 拿到 Token 的人可在局域网内控制该插板（断电/上电） |
| 拿到设备或文件的人 | 不需要"破解"口令——Token 本身就是明文，所以**口令哈希无盐是有意为之**（两版一致），不要把它当作强安全边界 |
| 建议 | 不要在公网直接暴露端口；确需外网访问时，用反向代理 + HTTPS + 额外的访问控制 |

### 11.2 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| **页面打不开** | 服务版：进程没起来 / 端口没映射 / 监听地址设成了 `127.0.0.1` | `docker compose logs` 看日志；确认 `ports` 与 `WEB_PORT` 一致、`WEB_LISTEN` 为空 |
| | 固件版：WiFi 没连上 | 看串口日志；必要时运行中长按 BOOT 键 5 秒恢复出厂，回到固件里的默认 WiFi |
| **忘记访问密码** | — | 服务版：**先看启动日志**（纯内存模式下每次启动都会打印新生成的密码）；持久化模式下可删掉配置文件后重启；想一劳永逸就设 `WEB_PASSWORD`。固件版：运行中长按 BOOT 键 5 秒 |
| **配置改完不生效 / 重启后丢失** | 先看启动日志里的"配置持久化"一行：若显示**已关闭**，说明当前是纯内存模式（没挂数据卷，或 `CONFIG_FILE=`）——改动本来就只在内存中生效 | 想持久化就挂载 `./data:/data` 并修好目录属主（见 §3.2）；纯内存模式是预期行为，不是故障 |
| **`miIO 异常` 一直亮/常亮** | Token 错、插板离线、IP 错、网络隔离（AP 隔离/不同子网） | 用 `miiocli` 等工具先确认能控制插板；检查 IP 与 Token |
| **握手成功但命令一直"未确认"** | Token 错（见 §10 提示） | 重新提取 Token |
| **频繁断电重启光猫** | Ping 目标被运营商屏蔽；阈值太短；光猫确实不稳 | 换 Ping 目标；加大 `断网阈值`；看日志里"断网已持续"是否持续增长 |
| **已熔断，不再自动重启** | 连续 5 次重启无效 | 修复根因后点「清除熔断状态」，或让网络连续在线 5 分钟自动解除 |
| **重启后立刻又重启光猫** | 冷却期太短；光猫启动慢 | 加大 `重启冷却` |
| **容器启动即退出** | ICMP socket 不可用（`checkICMPReady` 自检失败）；配置非法 | 看日志；确认 compose 里的 `sysctls: net.ipv4.ping_group_range=0 2147483647` 生效；确认 `DEVICE_IP`/`DEVICE_TOKEN`/Ping 目标格式正确 |
| **配置文件损坏导致起不来** | 掉电 / 磁盘满 | 不会 Fatal：程序会把坏文件改名为 `*.corrupt` 并回退环境变量；查看日志确认 |
| **看日志** | — | 服务版：`docker compose logs -f`（stdout）或管理页日志页（内存缓冲）；固件版：串口 115200 或管理页 |

## 12. 两版差异与已知限制

### 12.1 行为一致的契约

| 项目 | 约定 |
|---|---|
| 熔断阈值 | 1–10，默认 5；每次**触发**重启动作即计数（含未完成的动作） |
| 手动动作 | **不计入**熔断计数 |
| 熔断清零 | 连续在线满 5 分钟；或手动点「清除熔断状态」 |
| 断网判定 | 连续 2 次探测失败才开始计时 |
| siid / piid | 1–9999，不允许 0 |
| 时长写法 | `15s` / `10m` / `600` / `1m30s`；不支持小数与 ms |
| 参数字段留空 | 一律 = 保持不变，不报错 |
| Ping 目标校验 | 严格 IPv4，拒绝 `0.0.0.0`、`127.0.0.0/8`、等于插板地址 |
| `/status` 字段 | 字段名、类型、语义一致 |
| 动作名 | `reboot_modem` / `power_on` / `restart_self` / `factory_reset` / `clear_fatal`（固件另有 `apply_wifi`） |
| 前端 | 同一套徽章、同一张动作名映射表 |

### 12.2 平台差异（合理保留）

| 项目 | 服务版 | 固件版 |
|---|---|---|
| 运行环境 | Linux 容器 | ESP32-C3 |
| WiFi 相关配置 | 无（由宿主系统负责） | `wifiSsid` / `wifiRetry` / `wifi` `ip` `rssi` 状态字段 |
| 单次 ping 超时 | 可配（默认 1s） | 固定 1s |
| 稳定在线期 | 可用 `ONLINE_STABLE` 微调（默认 5m） | 编译期常量 5m |
| 日志缓冲 | 默认 8 MiB，可调；支持增量拉取 | 16 KiB（RAM 有限） |
| 日志持久化 | stdout → `docker logs` | 串口 |
| 额外配置项 | `WEB_LISTEN`、`CONFIG_FILE`、`LOG_BUFFER_SIZE`、`PUID/PGID`、`TZ` | 需重启生效的 `HTTP 端口`、`WiFi 重连间隔` |
| 恢复出厂 | 控制页按钮（删配置文件 + 状态文件后重启） | 控制页按钮 **或运行中长按 BOOT 键 5 秒** |
| 首次访问密码 | 随机生成，打印到日志 | 编译期默认口令 `admin` |
| 阻塞特性 | Web 服务独立协程，操作不影响页面 | 单线程：等待类操作已非阻塞，但"等一条命令确认"期间页面最多卡约 3 秒 |

### 12.3 已知限制

1. **无外部告警**：熔断、重启等事件只写日志与页面徽章，不发邮件/Webhook/MQTT。需要主动监控请轮询 `/status` 的 `fatal` / `reboots`。
2. **无法区分"宽带故障"与"光猫故障"**：只会按"外网不通"重启光猫。若故障在上游（区域断网），重启光猫没有帮助——熔断机制就是为了限制这种无用功。
3. **只有一次重启机会窗口**：熔断后必须人工介入，或等网络自愈并连续在线 5 分钟。
4. **服务版熔断计数是"当前累计"**：未达熔断阈值时，计数会在连续在线 5 分钟后清零，因此它反映"最近一轮连续故障中的动作次数"。
5. **固件版依赖 2.4G WiFi**：ESP32-C3 不支持 5G 频段。
6. **固件版 Flash 已占用约 80%**：继续加功能有超限风险（当前上限 1310720 字节）。
7. **无真机自动化测试**：两版都通过编译验证与逻辑层对照测试，但没有硬件在环测试；首次部署请按 [§11.2](#112-故障排查) 逐项确认。
8. **纯内存模式下熔断状态也不持久化**：进程重启 = 熔断清零、计数归零、访问密码重新随机。需要"重启后仍保持熔断"请用持久化模式。

## 13. 从源码构建与文件说明

### 13.1 服务版（Go）

要求 Go 1.26+（本仓库用 go1.27.1 验证）。项目**只支持 Linux**（依赖 ICMP DGRAM socket、`setuid/setgid`、`syscall.Exec`），源码带 `//go:build linux`。

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags "-s -w" -o modem-watchdog .
```

- 产物是**静态链接** ELF，可直接跑在 `busybox`（musl）等精简镜像里
- 交叉编译 ARM 主机（如 ARM NAS）：把 `GOARCH` 改成 `arm64`
- 自检：`gofmt -l .`（应无输出）、`GOOS=linux go vet ./...`（应无输出）
- 运行前自检：程序启动时检查 ICMP socket 是否可用，不可用直接退出（避免"永远探测不到网络 → 每次阈值都重启光猫"）

### 13.2 固件版（ESP32）

- **Arduino IDE**：打开 `.ino`，选 `ESP32C3 Dev Module`，编译上传
- **arduino-cli**：

```bash
arduino-cli compile --fqbn esp32:esp32:esp32c3 --warnings all modem-watchdog.ino
```

依赖：`esp32` core 3.x、`ESP32Ping` 库（mbedtls 由 core 自带）。

> ⚠️ 文件里有一处 `miio_drain_response(...)` 使用了默认参数。arduino-cli **不会**为"带默认参数的函数"生成自动原型，所以默认值已刻意写进文件顶部的手写声明区——**不要在函数定义处重复写默认值**，也不要把它挪到定义之前调用。

| 文件 | 说明 |

| [`modem-watchdog`](modem-watchdog) | 编译好的 Linux x86-64 静态二进制（compose 挂载的就是它） |
| [`docker-compose.yml`](docker-compose.yml) | 服务版部署编排 |
| [`go.mod`](go.mod) / [`go.sum`](go.sum) | Go 模块定义（依赖 `golang.org/x/sys`） |
| `<CONFIG_FILE>`（默认 `/data/config.json`） | 运行时生成的配置（服务版）；删除它 = 恢复出厂。**纯内存模式下不产生** |
| `<CONFIG_FILE>.state` | 运行时生成的熔断/计数状态（服务版）；删除它 = 清熔断。**纯内存模式下不产生** |

固件版配置全部在设备 NVS 里，不产生文件。
